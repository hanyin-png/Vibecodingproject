## 问题定位页

**Q1 业务闭环是什么？**
台账录设备 → 监测看趋势 → 评估算寿命 → 寿命低或数据异常就出预警 → 预警进规则引擎出诊断建议 → 一键生成工单 → 工单流转到完成。

**Q2 系统给谁用、解决什么问题？**
设备运维人员。把"坏了才修"变成"坏之前就修"，省突发停机损失和过度维修浪费。

**Q3 预警三级阈值哪来的？**
≤30 严重 / ≤60 警告 / ≤90 提示。工程惯例加业务常识：30 循环内必须停机，90 以内开始关注。代码里可改。

## 方案架构页

**Q4 为什么前后端分离？**
任务书要求 B/S 架构；分离后接口化，换前端或接别的系统都方便。

**Q5 为什么 SQLite 不用 MySQL？**
一万多行数据足够；免装服务、数据库就是一个文件，拷到任何电脑都能跑。

**Q6 模型为什么离线训练、在线只推理？**
演示要立刻出结果；工业系统也普遍这么做，模型定期离线更新。

**Q7 四个技术方向各起什么作用？（必考）**
孤立森林发现异常 → 随机森林评估严重度 → 规则引擎给处置建议 → 工单闭环执行；LSTM 做时序建模对比实验。

## 数据集页

**Q8 C-MAPSS 是什么？FD001 什么特点？**
NASA 公开的涡扇发动机退化仿真数据集，PHM 领域基准。FD001 单工况、单故障模式（高压压气机退化）。

**Q9 RUL 标签怎么构造？为什么截断 125？**
最大循环数 − 当前循环数。健康初期退化信号弱，不截断标签会失真。

**Q10 为什么剔除 7 个传感器列？**
s1/s5/s6/s10/s16/s18/s19 恒定不变，没有信息量，留着干扰模型。

**Q11 归一化为什么只用 train 集拟合？**
防数据泄露：test 模拟在役设备，拿不到未来分布。scaler 存盘，推理用同一份。

## 模型对比页

**Q12 随机森林为什么适合？**
输入是 57 维统计特征（均值/标准差/末值/斜率 + 循环数）。随机森林对表格型特征稳定、不怕量纲、能输出特征重要性。

**Q13 LSTM 和普通网络的区别？**
门控机制能记住长期退化趋势；普通网络把每个时间点当独立样本。

**Q14 为什么两个模型精度差不多？**
FD001 是单工况小数据集，随机森林的人工特征利用先验更充分；小数据场景特征工程比模型复杂度更关键。

**Q15 MAE 和 RMSE 的区别？**
MAE 平均绝对误差；RMSE 对大偏差惩罚更重。我的 MAE≈11.8、RMSE≈15.5，说明没有离谱的个别预测。

**Q16 模型体积 90MB→13MB 怎么做的？**
限制树最大深度 12、叶子最少 5 样本，体积压缩 86%，精度几乎不变。为解决 GitHub 100MB 限制。

## 异常检测与规则引擎页

**Q17 孤立森林原理？**
随机切分数据空间，异常点几刀就被孤立、平均路径短。

**Q18 为什么用无监督？**
工业故障样本稀缺，孤立森林只用健康数据就能训练。

**Q19 规则引擎和直接问大模型的区别？**
结论确定、可追溯、离线可用。

**Q20 15 条规则哪来的？**
按 FD001 故障机理和运维排障习惯编写：A 类 9 条部件级、B 类 3 条寿命阈值、C 类 3 条兜底。先软后硬、先外后内。

**Q21 传感器坏了会不会误判成设备坏？**
规则 A8 处理这种背离：s13/s14 异常但 s8/s9 正常 → 判传感器故障；C1 也是"寿命正常先查测量链路"。

## 高危代码段（随机指哪段讲哪段）

1. **随机森林特征提取**（rul_rf.py window_stats）：20×14 窗口 → 均值/标准差/末值/斜率 56 维 + 循环数 = 57 维；斜率是 polyfit 一次项系数。
2. **规则引擎 condition**（rules_engine.py）：每条规则一个 lambda；`{"s7","s11","s12"} <= s` 是集合包含判断；全部规则遍历后按 priority 排序。
3. **异常检测 detect**（anomaly.py）：scaler 归一化 → 孤立森林 predict 打分（-1 异常）→ 命中后用设备自身基线 3σ 找具体异常传感器。
